# threads

A container and the models that follow it live in one thread: `assertOwnThread` and the model constructor say so with
`Q_ASSERT_X`, which is compiled out of a release build. Tests: `capability_edge_thread_rules` (debug asserts, each
scenario in a forked child that must die of SIGABRT), `limit_edge_thread_no_assert` (`QT_NO_DEBUG` defined before any
include: what happens with the rule not enforced), `capability_edge_thread_lifetime`, and the pinned
`limit_edge_thread_stale_model` and `limit_edge_thread_queued_about`. Every wait is bounded; each test ran 150 times in
a row without a failure (one race that showed in 300 runs is gated, see T-19). A data race is not tested: where two
threads would touch the container at once the test lets one wait for the other, or does not run it. No QTBUG id is
cited: the cases came from the Qt documentation of moveToThread, deleteLater and queued connections.
