# views-qml

Widget views (QListView, QTableView, QTreeView, offscreen) and QML views (ListView, Repeater, TableView in a
QQuickWindow with the software backend) over the observable container models. Tests: `capability_edge_view_widgets`,
`limit_edge_view_edit_role`, `capability_edge_qml_listview`, `capability_edge_qml_views`,
`limit_edge_qml_rowcount_binding`. Where Qt has a model of its own that behaves the same way (QStringListModel,
QStandardItemModel), the view is shown that model too, under the same change, and the two must agree: a difference is
the container model's and everything else is the way the view works. For a map, whose rows have no Qt counterpart, the
model's announced rows are replayed onto a QStringListModel. Qt behaviours found on the way, none of them the model's:
a SingleSelection view moves its current index to the neighbour of a removed current row and selects it (clearing the
rest), and ListView keeps its currentIndex number across a model reset. No QTBUG id is cited: none of these was
looked up as a bug.
